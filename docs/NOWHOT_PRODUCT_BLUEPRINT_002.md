## 결론

지금핫의 기준 모델은 하나의 서비스를 복제하는 방식이 아니라 아래 조합으로 정한다.

1. Techmeme: 높은 정보 밀도와 이슈별 출처 클러스터
2. Google Trends: 검색량, 상승률, 시작 시각, 활성 상태처럼 "왜 지금 뜨는지" 보여주는 지표
3. 뉴닉과 Axios: 짧고 이해하기 쉬운 자체 해설 문법
4. Ground News와 Particle: 한 사건을 여러 출처로 묶고 출처 수와 관점을 투명하게 표시하는 상세 화면
5. 네이버 뉴스 랭킹: 한국 사용자가 이미 익숙한 탭, 순위, 시간 표기

목표 제품은 **오늘의 브리핑이 홈이고 실시간 피드는 그 안의 한 모드인 단일 서비스**다. `/`와 `/live`가 서로 다른 제품처럼 보이는 현재 구조는 폐기 대상이다.

## 확인된 현재 문제

2026-08-10 로컬 실데이터 기준이다.

- `/`의 가시 본문은 약 1,045자다.
- `/briefing`의 가시 본문은 약 5,157자다.
- 홈은 보유한 브리핑 자산의 약 20%만 사용한다.
- `/live`에는 내부 기능 링크가 있지만 `/`로 돌아가는 링크가 없다.
- 홈은 자체 콘텐츠를 보여주기보다 심사 목적을 설명하는 임시 지면처럼 보인다.
- 브리핑, 실시간 피드, 랭킹, 리포트가 하나의 이동 체계로 묶이지 않는다.

### Techmeme

가져올 요소:

- 한 이슈를 대표 제목, 짧은 설명, 주요 출처, 추가 출처, 사회 반응으로 묶는다.
- 데스크톱 첫 화면을 핵심 뉴스, 스폰서, 최신 뉴스의 세 영역으로 고밀도 구성한다.
- 브랜드와 HOME, RIVER, ARCHIVE 이동을 항상 노출한다.
- 광고를 Sponsor Posts로 명확히 구분하면서 정보 흐름을 해치지 않는다.

가져오지 않을 요소:

- 작은 글자와 과도한 링크 밀도
- 한국 일반 사용자가 이해하기 어려운 원문 중심 문장
- 사람 편집자 상시 운영을 전제로 한 구조

### Google Trends

가져올 요소:

- 상승률, 반응량, 시작 시각, 활성 또는 종료 상태
- 4시간, 24시간, 48시간, 7일 필터
- 행을 누르면 추이와 관련 항목을 같은 맥락에서 펼치는 구조
- 데이터 갱신 시각을 눈에 띄게 표시

가져오지 않을 요소:

- 설명 없이 검색어와 숫자만 나열하는 표
- 지금핫 데이터가 증명하지 못하는 검색량 흉내

### Ground News

가져올 요소:

- 같은 사건을 여러 출처로 클러스터링
- 카드에서 출처 수와 분포를 먼저 표시
- 모두에게 같은 Top Stories와 개인화된 My Feed를 분리
- 상세 화면에서 요약, 출처, 관점 비교를 한곳에 제공

가져오지 않을 요소:

- 검증 체계 없이 좌·중·우 편향 점수를 만드는 기능
- 구독 전환을 위해 첫 화면을 막는 큰 프로모션

### Particle

가져올 요소:

- `86 articles · 1h ago`처럼 출처 수와 최신성을 제목보다 먼저 이해시키는 표기
- 대표 이미지, 한 문장 제목, 한 문장 의미를 한 카드 안에 완결
- Overview, ELI5, Opposite Sides처럼 같은 사건을 여러 깊이로 읽는 구조
- 원문을 근거로 답하는 질문 기능은 장기 후보로 둔다.

가져오지 않을 요소:

- 첫 화면을 가득 채우는 큰 이미지 카드
- 초기 단계부터 도입하는 고비용 대화형 AI
- 근거 검증이 어려운 자동 요약의 무제한 발행

### 뉴닉과 Axios

가져올 요소:

- 제목만 읽어도 사건과 의미가 함께 이해되는 한국어
- `무슨 일`, `왜 중요한가`, `다음 관전`의 짧은 문법
- 광고를 AD로 분명히 표시하면서 편집 콘텐츠와 같은 품질로 제작
- 전체 브리핑을 읽지 않아도 핵심을 훑을 수 있는 계층

가져오지 않을 요소:

- 첫 화면의 큰 단일 기사와 큰 구독 배너
- 지금핫의 중립적 데이터 제품 성격과 맞지 않는 캐릭터 말투

### 네이버 뉴스 랭킹

가져올 요소:

- `많이 본`, `댓글 많은`, 날짜 탭의 익숙한 구조
- 순위, 시간, 썸네일을 한눈에 비교하는 밀도
- 상단의 일관된 서비스 내비게이션과 홈 복귀

가져오지 않을 요소:

- 같은 사건이 언론사별로 반복되는 목록
- 인기 순위를 중요도처럼 보이게 하는 구성

## 목표 정보 구조

### 공통 셸

모든 페이지에서 같은 헤더를 사용한다.

- 브랜드 로고: 항상 `/`로 이동
- 주 내비게이션: `오늘`, `실시간`, `분야`, `저장`
- 현재 모드는 탭 또는 세그먼트 상태로 표시
- 모바일 상세에서는 뒤로가기와 홈을 모두 제공
- 목록에서 상세로 이동한 뒤 브라우저 뒤로가기를 누르면 이전 스크롤 위치를 복원

### `/` 오늘의 브리핑

홈 자체가 전체 오늘의 브리핑이다. 별도의 홍보형 소개 화면을 두지 않는다.

1. 날짜, 마지막 갱신 시각, 수집 출처 수
2. 오늘의 핵심 이슈 5개
3. 각 이슈의 `무슨 일`, `왜 뜨나`, 반응량, 상승세, 출처 수
4. 분야별 핵심 이슈
5. 실시간 상승 이슈 스트립
6. 데이터 설명과 선정 방법
7. 날짜별 브리핑 아카이브

데스크톱 첫 화면에는 핵심 이슈 3개 이상, 모바일에는 첫 이슈 전체와 두 번째 이슈의 시작이 보여야 한다.

### 이슈 카드

모든 이슈 카드는 아래 고정 필드를 사용한다.

- 이슈 제목
- `무슨 일`: 확인된 사실 한 문장
- `왜 뜨나`: 지금 반응이 커진 이유 한 문장
- `지금 수치`: 출처 수, 반응량, 증가율, 시작 시각, 활성 상태
- `관전`: 아직 확정되지 않은 다음 확인점
- 출처 칩 2~4개와 `전체 출처 보기`
- 저장과 공유

### `/live` 실시간 모드

- 별도 앱처럼 보이지 않고 공통 셸 안에서 `실시간` 탭만 활성화한다.
- 기존 개인화, 소스 필터, 상세, 공유 기능은 유지한다.
- 화면 상단에 `오늘의 브리핑으로` 링크를 항상 노출한다.
- 상세는 가능하면 인라인 패널 또는 오버레이로 열고 닫을 때 목록 위치를 보존한다.
- 검색 색인과 심사 광고 분리 원칙은 유지한다.

### 상세와 아카이브

- `/story/:clusterId`: 한 이슈의 타임라인, 측정 근거, 관련 출처, 지금핫 해설
- `/briefing/YYYY-MM-DD`: 그날의 완결된 브리핑
- `/briefing`: 날짜별 아카이브 인덱스
- 현재 `/briefing`의 오늘 내용은 `/`로 통합한다.

## 콘텐츠 생산 파이프라인

```text
원문 수집
  -> 중복 제거
  -> 동일 사건 클러스터링
  -> 반응량과 상승 속도 계산
  -> 확인된 사실 추출
  -> 무슨 일 / 왜 뜨나 / 관전 초안 생성
  -> 출처 교차 확인과 금칙 검수
  -> 홈, 실시간, 상세, 아카이브에 같은 데이터로 투영
```

자체 콘텐츠 최소 조건:

- 외부 제목 복사만으로 발행하지 않는다.
- 이슈마다 지금핫의 측정값 또는 교차 출처 근거가 하나 이상 있어야 한다.
- `무슨 일`과 `왜 뜨나`는 서로 다른 역할을 해야 한다.
- 추정은 확인된 사실과 분리하고 `관전`에 둔다.
- 같은 이슈를 페이지별로 다시 생성하지 않고 하나의 클러스터 원본을 사용한다.
