## 결론

제품 방향은 맞다. 선택 분야를 공유 판본으로 만들고 하루 세 번 저장하며, 근거와 검수
원장을 분리하고, 미제공 양질 보도를 제한 이월하는 골격은 목적에 기여한다.

그러나 현재 시스템이 가장 잘하는 일은 `42건을 안정적으로 채우는 것`이다. 핵심 상품인
`따로 찾아볼 필요가 없는 사건 선별과 기자식 자체 편집`은 아직 증명되지 않았다. 신규
기능·소스·카테고리·LLM 범위를 더 늘리면 목적 적합성보다 생산량을 최적화할 위험이 크다.
따라서 다음 단계는 기능 확장이 아니라 독자에게 실제로 보이는 문장과 사람 정답표의
폐쇄다.

읽었다. 다만 실제 Techmeme, Ground News, Particle, 뉴닉, 네이버 임직원이 참여한 것이
아니다. 아래 이름은 해당 서비스와 직무의 평가 기준을 모사한 `독립 직무 렌즈`다.

## 직접 확인한 사실

- 실제 시스템 시계 저장 증거는 모닝·런치 `2/3`이며 이브닝은 미도래였다.
- 아침·낮 검수 패킷의 실제 2인 완료는 `0/84`다.
- 비저장 이브닝 재생은 `42/42` 기계 PASS지만 검수 행의 `reader` 동결은 `0/42`다.
- 활성 모닝 검수판 42행의 독자 문장은 제목·요약만 42종이다.
- 같은 42행의 `왜 중요한가`는 14종, `왜 지금`은 3종, `다음 확인`은 3종이다.
- 한 `다음 확인` 상용구가 42행 중 33행에 반복됐다.
- 레지스트리 111개 소스 중 명시 `sourceRole`은 3개, `ownershipGroup`은 6개,
  `syndicationGroup`은 0개다. 나머지는 fallback 분류에 의존한다.
- 전체 회귀 `1,094/1,094`는 코드 계약 안정성 증거이며 편집 품질 증거가 아니다.

## 공통 P1

### PAR-P1-01 · 독자 문장이 기계 PASS 범위 밖

비저장 세 판 검수 패킷은 실제 reader payload를 동결하지 않고도 `42/42` PASS가 가능하다.
문장 형식·근거 행 존재와 독자가 읽는 제목·요약·중요성·변화의 품질이 분리돼 있다.

### PAR-P1-02 · 사건별 자체 편집보다 카테고리 상용구

`왜 중요한가`, `왜 지금`, `다음 확인`이 사건의 새 사실·수치·결정에서 만들어지지 않고
카테고리와 근거 모드별 고정 문장으로 반복된다. 현재 결과는 자체 브리핑보다 제목 목록에
상용구를 붙인 형태에 가깝다.

### PAR-P1-03 · 사람 품질 정답표 0

아침·낮 84행의 포함 가치, 사건 병합, 제목 충실도, 근거 충분성, 분야 적합성을 두 사람이
독립 완료한 행은 없다. `14/14 분야`, `42건`, `publishable`은 공급과 형식 상태다.

### PAR-P1-04 · 사실 상태 중심 사건 모델 부족

사건의 `주체·행동·대상·시각·상태`보다 제목과 URL, 출처 수, 관련 보도량에 의존한다.
따라서 같은 사건의 다른 기사 재등장과 실제 새 사실·수치·결정의 구분이 사람 정답표 없이
검증되지 않았다.

### PAR-P1-05 · 출처·주장 신뢰 메타데이터 공백

명시된 출처 역할·소유·전재 그룹이 소수이고, 주장 계보는 근거 ID 존재와 해시를 확인하지만
문장이 원문으로 실제 지지되는지까지 검증하지 않는다. 24시간 이월에도 정정·철회·후속
반전 상태 확인이 없다.

### PAR-P1-06 · 장기 내구성·비용·조합 상한 미정

관리자 GET이 재고와 패킷을 만들 수 있고, 스케줄러는 단일 프로세스 타이머이며, 사용자
카테고리 조합 상한이 없다. 임시 경로 단일 JSON과 조합당 LLM 상한은 다중 writer·백업·복원·
일·월 비용·대규모 조합의 운영 증거가 아니다.

## 유지할 것

1. 실제 슬롯과 사람 검수 상태를 미리 PASS로 올리지 않는 증거 경계
2. 최초 판본·최초 슬롯 관측을 덮어쓰지 않는 불변 원장
3. 공유 판본과 응답 전용 개인화로 사용자별 전체 재생성을 피하는 비용 구조
4. 현재 슬롯 우선, 기제공 URL·커뮤니티·기한 초과 제외 이월 규칙
5. 최상단 `지금핫 NowHot 맞춰가는 중` 정체성과 오늘·실시간 고정 전환

## 다음 허용 범위

1. 실제 독자 `reader` payload를 검수 패킷에 그대로 동결하고 독자 화면과 바이트 수준으로
   같은지 검증한다.
2. `reader:null`, 미번역 영어, 절단 제목, 내부 용어, 반복 상용구, 커뮤니티를 보도라고 쓰는
   문장을 발행 HOLD 조건으로 둔다.
3. 아침·낮 84행을 실제 서로 다른 두 사람이 전수 독립 검수하고 불일치를 별도 조정한다.
4. 기존 자동 스케줄러의 실제 19시 관측은 계속하되 성공을 미리 주장하지 않는다.
5. 독자 품질 기준선 뒤에 사건 상태 모델, 출처 메타데이터, 내구 스케줄러, 조합·비용 상한을
   순서대로 폐쇄한다.

- 테스트 수, `42/42`, `14/14`를 제품 품질 PASS로 해석하는 일

## 30일 실패 시나리오

현재 방식으로 기능과 예외만 늘리면 관리자 화면과 회귀 수치는 계속 좋아진다. 반면 사용자는
반복 상용구, 단일 출처 제목 변주, 같은 사건의 새 사건 재등장, 저가치 PR과 분야 오분류를
하루 세 번 받는다. 정보량은 많지만 판단 가치는 낮아 다시 원문을 찾아다니게 된다. 그때
NowHot은 개인 브리핑이 아니라 길고 자동화된 제목 모음으로 굳어진다.

실제 19시판 성공, 다일 안정성, 운영·광고·계정·배포 승인을 증명하지 않는다.
