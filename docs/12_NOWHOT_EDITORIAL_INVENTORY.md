## 해결한 공백

이전 로컬 오늘판은 사용자가 `/api/today`를 열 때만 선택 조합의 판을 저장했다.
서버가 발행 시각을 놓치면 공용 스케줄러도 가장 최근 슬롯 하나만 채웠고, 저녁에
모닝판을 요청해도 후보 시간창은 요청 당시 저녁을 기준으로 계산될 수 있었다.

이번 계약은 하루 세 판을 요청 결과가 아니라 저장 재고로 만든다.

1. 모닝·런치·이브닝의 기준 시각을 각각 KST 07:00·12:00·19:00으로 고정한다.
2. 기본·대표 이용자가 많은 조합을 먼저 잡고, 그 조합 안에서 필요한 누락 슬롯을 시간순으로 백필한다.
3. 사용자별로 만들지 않고 정렬된 선택 카테고리 조합별로 한 번 만들어 공유한다.
4. 저장 판이 있으면 요청은 그 판을 읽고, 없으면 같은 계약으로 즉시 보완한다.

## 슬롯 as-of 계약

`FeedEngine.briefing`과 `todayEdition`은 선택적으로 `asOfMs`를 받는다. 로컬 개인판은
반드시 슬롯 발행 시각을 넘긴다.

- 사용 가능 시각: `max(firstSeenAt, publishedAt)`
- 포함 조건: 사용 가능 시각이 슬롯 기준 시각보다 늦지 않아야 한다.
- 신선도 조건: 슬롯별 `windowHours` 안에 있어야 한다.
- `generatedAt`: 요청 시각이 아니라 슬롯 기준 시각이다.
- 미래 슬롯: 명시적 요청에는 `409 EDITORIAL_SLOT_NOT_DUE`를 반환한다.
- 07시 전 기본 요청: 전날 이브닝 저장 판을 대상으로 한다.
- 화면 탭: 미도래 슬롯은 당일 판에서만 잠그고, 07시 전 표시되는 전날 세 판은 모두 다시 열 수 있다.

따라서 20시에 누락 모닝판을 만들더라도 07시 이후 처음 관측되거나 발행된 항목은
모닝판 후보에 들어가지 않는다.

## 조합 공유 계약

유효 선택은 기존 우선순위를 그대로 쓴다.

1. `briefingCategories`
2. 설문 카테고리
3. 기본 체험 조합

카테고리는 유효 ID만 남기고 중복 제거·정렬한다. 키는
`v17:<sorted category ids>`이며 사용자 ID, 세션 ID, 이메일, 닉네임을 넣지 않는다.
같은 조합을 고른 이용자가 여러 명이어도 슬롯당 저장 판은 하나다. 관리자 영수증에는
조합별 집계 인원만 표시한다.

## 제한 백필 큐

- 예정 판 수: `현재까지 도래한 슬롯 수 × 고유 선택 조합 수`
- 07시 전 복구 창: 오늘 슬롯 대신 전날 세 슬롯의 누락을 점검
- 정렬: 기본 조합·대표 인원이 큰 조합 우선, 같은 조합 안에서는 모닝→런치→이브닝 선행판 순서
- 기본 회당 상한: 12판
- 환경 설정: `NOWHOT_EDITORIAL_INVENTORY_BATCH`, 최대 48판
- 점검 간격: 기본 5분
- 시작 점검: 로컬 서버 기동 30초 뒤
- 새 선택 저장: 즉시 비동기 점검 예약
- 동시 요청: 날짜·슬롯·조합 in-flight 약속을 공유해 중복 저장 방지

상한 뒤의 누락분은 다음 점검에서 이어서 처리한다. 낮은 우선순위 조합의 오래된 누락이
기본 현재판을 밀지 않으며, 같은 조합은 직전 판이 먼저 생겨 변화 계보가 끊기지 않는다.
이용자 수가 아니라 고유 조합 수에 비례하므로 같은 취향 이용자가 늘어도 생성 비용은
늘지 않는다.

## 과거 슬롯 복원 순서

늦은 백필은 현재 화면용 소스 상한을 먼저 적용하지 않는다. 48시간 누적 풀에서 슬롯
발행 시각 이후 처음 관측되거나 발행된 항목을 먼저 제외하고, 남은 항목을 그 시점의
최신순으로 정렬한 뒤 소스 상한·URL 중복 제거를 적용한다. 그 다음 현재판과 같은
항목별 분류를 적용해 상한 밖 과거 행이 소스 등록 분야로 되돌아가는 것을 막는다.
교차보도 수도 그 as-of 항목만으로 다시 계산해 나중에 늘어난 출처 수를 과거
문장으로 소급하지 않는다.

이 복원은 서버가 당시 수집해 48시간 풀에 보존한 항목만 되살린다. 서버가 꺼져 있어
아예 수집하지 못한 원천 데이터나 당시 반응 수치의 정확한 상태까지 복원하는 기능은
아니다. 따라서 늦은 백필은 계속 실제 정시 실행 증거와 분리한다.

## 버전·보존

이전 무버전·`v2:`~`v8:` 판본은 삭제하거나 덮어쓰지 않는다. `v3:`는 슬롯
as-of에 주장 계보·근거 해시·선택형 LLM 영수증을 더한 보존 판이고, `v4:`는 선택
분야별 충족도 영수증과 분류 무결성 규칙을 더한 보존 판이다. `v5:`는 선택 수 비례
14~42건 판본 예산과 공급 분야 최소 깊이를 더한 보존 판이다. `v6:`는 as-of 우선
백필 순서, `v7:`·`v8:`은 분류·배분 수정의 중간 검증 판이다. `v9:`는 현재·과거
분류 parity, 정치 선택 투영, 생성·판정 최소값 통합을 적용한 보존 판이다. `v10:`은
동일 발행사의 중계·직접 RSS를 한 운영그룹으로 접은 보존 판이다. `v11:`은 같은
사이트의 일반·분야 섹션과 라벨·소스 ID 표기 차이까지 한 운영그룹으로 수렴한 보존
판이다. `v12:`는 정규화 제목 완전일치 또는 canonical 원문 URL 동일만 한 문단으로
결합하고 태그·부분 제목은 결합 근거에서 제외한 보존 판이다. `v13:`은 이 결합 계약을
유지하면서 게임 일반 뉴스 공급과 출처 균형 폴백을 추가한 역사판이다. `v14:`~`v16:`은
후속 계약을 확인하는 동안 생성된 append-only 중간 판이며 삭제하지 않는다.

현재 `v17:`은 판본 변화 4, 분야 충족 4, 주장 계보 4, 계보 지문 5, 편집 품질 12를
하나의 호환성 계약으로 묶는다. 하나라도 현재 코드와 다르면 새 저장판 생성을
fail-closed로 중단한다. 직전 슬롯에 같은 `v17` 조합이 없으면 같은 카테고리 조합의
가장 최신 구버전 판을 변화 비교 기준으로 읽어 버전 교체 때 사건 연속성이 끊기지
않게 한다. 새 판본도 기존 원자적 JSON 저장과 400일 보존을 재사용하며 재시작 뒤
그대로 읽는다.

## 관리자 영수증

개발관리의 `개인판 슬롯 재고`에서 다음을 함께 본다.

- 고유 선택 조합과 대표 인원
- 현재 시각까지 예정된 판 수
- 저장·발행 가능·보류·누락 수
- 이번 점검 생성 수와 남은 백필
- 슬롯별 KST 기준 시각
- `v17:` 조합 키와 카테고리
- 현재 코드와 저장 스냅샷의 5개 계약 버전 호환성
- 회당 상한과 새 LLM 호출 수

`inventory_complete`는 모든 저장 판이 발행 가능할 때만 쓴다. 저장은 끝났지만 최소
발행 조건을 못 채운 판이 있으면 `inventory_complete_with_holds`로 분리한다. 어느
상태도 실제 시간차 수집 충분성이나 사람 편집 품질 PASS를 뜻하지 않으며, 저장 경로와
누락·발행 보류 여부만 증명한다.

실제 시간 경과 실행은 `NOWHOT-ELAPSED-EDITION-EVIDENCE-CONTRACT-001`이 별도로
기록한다. 재고 영수증은 `startedAt`, `completedAt`, `durationMs`를 남기며, 시스템
시계 기준 저장 완료가 발행 후 10분을 넘으면 늦은 백필이다. 큐 시작이 빨랐다는
사실만으로 정시 실행으로 올리지 않으며 이후 상태도 덮어쓸 수 없다.

## 검증

- 슬롯 시각 계산과 미래 슬롯 차단
- 늦은 요청에서도 슬롯 이후 항목 제외
- 현재 소스 상한 밖으로 밀린 과거 항목의 48시간 풀 as-of 복원
- as-of 이후 늘어난 교차보도 값의 과거 판 소급 차단
- 같은 카테고리 조합의 1회 공유 생성
- 사용자 식별자 없는 판본 키
- 핵심 조합 우선·조합 내부 시간순 선행판 처리와 회당 상한
- 큐 시작이 아니라 실제 저장 완료시각·소요시간 기록
- 무버전·`v2:`~`v16:` 판 보존과 `v17:` 재시작 생존
- v11 전체 분야 재생에서 v10의 섹션·표기 중복 2건이 새 키에 재사용되지 않음
- v12 전체 분야 재생에서 v11의 사건 오병합 2건이 새 키에 재사용되지 않음
- v13 현재 풀 재생에서 게임 일반 뉴스 공급·출처 균형과 전 분야 14/14 충족 확인
- v17 현재 계약 일치 PASS와 불일치 fail-closed
- v17 부재 시 같은 조합의 최신 구버전 판을 직전 판으로 읽고, 같은 v17이 있으면 우선하는 연속성 대조
- 현재 상한 밖 과거 혼합게시판 글에 현재 분류 규칙 재적용
- 로컬 플래그가 꺼지면 기존 홈·API 유지
