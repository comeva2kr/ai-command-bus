# 안심스캔 — 아이 먹거리 안심 카메라

> 바코드를 비추면 **우리 아이 기준** 점수와 판정(추천·주의·비추천·먹이지 마세요)이 나오고,
> 비추천이면 **지금 쓰는 쇼핑몰 안에서** 바로 살 수 있는 더 나은 대체품을 보여준다.
> 오프라인은 카메라, 온라인은 브라우저 확장.

## 왜 만드나

부모는 마트·쇼핑몰에서 아이 간식과 가공육을 고를 때 뒷면 원재료를 읽을 시간이 없다.
알레르기·아토피·성조숙증 같은 걱정은 결국 "뭘 먹이느냐"로 이어지는데, 지금 정보는
공포 마케팅(“이 성분이 독이다”)이거나 너무 어렵다.

해외에선 ToxScan 같은 스캐너가 같은 문제를 푼다. 우리가 다르게 가는 지점:

| | 해외 스캐너식 | 안심스캔 |
|---|---|---|
| 판정 근거 | MSG·씨앗기름까지 빨간불 | 감점마다 **근거 등급(A/B/C)과 출처**. MSG처럼 안전성 평가가 끝난 성분은 감점 없이 "오해 바로잡기"로 표시 |
| 기준 | 모두에게 같은 점수 | **아이 나이**(당·나트륨 기준), **알레르기**(무조건 차단), **걱정거리**(주의력·체중·성조숙증·아토피)로 개인화 |
| 대체품 | 앱이 고른 매장 목록 | **지금 보고 있는 몰**(쿠팡·네이버·컬리·SSG·11번가) 링크를 맨 앞에 |
| 순위 | — | 광고·제휴와 무관. 정렬 키는 점수뿐 |

근거 기반이 윤리 문제만은 아니다. 실제 브랜드 제품에 "비추천"을 붙이는 서비스라,
근거 없는 감점은 그대로 명예훼손·업무방해 리스크가 된다.

## 쓰는 흐름

**오프라인(매장)** — PWA를 열고 바코드를 비춘다.
1. 바코드 → 식약처 식품안전나라 DB에서 품목보고번호 → 원재료
2. DB에 없거나 iOS(실시간 바코드 인식 미지원)면 → **라벨 사진** 한 장 → 원재료·영양정보 전사(Claude 비전) → 같은 점수 엔진
3. 판정 + 이유 4개 + "더 안전한 선택 N개" (각각 무엇이 나아졌는지: "아질산나트륨 없음", "나트륨 520mg → 210mg")

**온라인(쇼핑몰)** — 크롬 확장을 깔고 상품 상세 페이지를 연다.
1. 「전자상거래 상품정보제공 고시」에 따른 **필수 표기정보 표**(원재료명·영양성분·알레르기)를 텍스트로 읽는다 — 이미지 OCR보다 싸고 정확
2. 점수는 확장 안에서 계산(아이 정보가 기기 밖으로 안 나감)
3. 오른쪽 아래 배지 "안심 53 비추천" → 누르면 이유와 대체품. 비추천·차단이면 자동으로 펼침
4. 대체품 구매 버튼은 **같은 몰** 링크

### 성조숙증·아토피에 대해 정직하게

- **성조숙증**: 직접 인과가 확인된 식품첨가물은 아직 없다. 확립된 위험요인은 소아비만이라,
  '성조숙증 걱정'을 고르면 당·열량 항목을 1.5배 엄격하게 본다. 화면에도 그렇게 쓴다.
  포장재 환경호르몬(비스페놀·프탈레이트)은 라벨에 안 나와 판정할 수 없다.
- **아토피**: 아이마다 악화 식품이 다르다. 일괄 감점 대신 의심 식품을 알레르기 목록에
  등록하게 하고, 등록된 성분은 바로 걸러낸다. (다음 단계: 식품 일기로 증상과 연결)
- 앱 문구는 "예방"·"치료"를 약속하지 않는다. "위험요인을 줄이는 선택"까지만.

## 코드 구조

```
src/ansim/
  core/            점수 엔진 — 서버·PWA·확장이 같은 코드를 쓴다 (node 전용 import 금지)
    allergens.js   알레르기 표시대상 매칭 (메밀≠밀, 땅콩버터≠우유 같은 오탐 방지)
    additives.js   첨가물 근거 사전 (등급·출처·감점·걱정거리 태그)
    ingredients.js 원재료명 파서 (괄호 중첩, '같은 제조시설' 분리)
    nutrition.js   영양정보 파서 + 나이별 기준
    categories.js  분류 (대체품은 같은 분류 안에서만)
    score.js       analyzeProduct(product, profile)
    alternatives.js rankAlternatives — 같은 분류·이 아이에게 안전·추천 등급, 개선점
    malls.js       몰 감지·구매 링크 (지금 몰 우선, 상세 URL 없으면 몰 검색)
    notice.js      쇼핑몰 상품정보제공고시 표 → 제품
  catalog.js       바코드 조회·대체품 후보 (지금은 가상 예시 17개)
  mfds.js          식품안전나라 C005(바코드)·C002(원재료) 어댑터
  label-reader.js  라벨 사진 → 원재료·영양정보 전사 (Claude 비전, 판정은 안 시킴)
  server.js        PWA + API
  public/          PWA (카메라 BarcodeDetector, 라벨 촬영, 결과·대체품)
extension/ansim/   크롬 확장 (MV3). core/는 tools/build-ansim-extension.mjs가 복사
```

### 실행

```bash
npm run ansim                       # http://localhost:4100
MFDS_API_KEY=… npm run ansim        # 실제 바코드 조회 (식품안전나라 무료 키)
ANTHROPIC_API_KEY=… npm run ansim   # 라벨 사진 분석 켜기
node --test test/ansim-*.test.js
```

확장: `node tools/build-ansim-extension.mjs` → 크롬 `chrome://extensions` → 개발자 모드 →
"압축해제된 확장 프로그램 로드" → `extension/ansim`. 아이콘을 눌러 아이 정보를 넣는다.
대체품 서버 주소를 비우면 내장 예시 카탈로그를 쓴다.

카메라는 HTTPS(또는 localhost)에서만 열린다. 휴대폰 실기기 테스트는 HTTPS 배포가 필요하다.

## 배포 전 검증 목록 (이 개발 환경에선 *.go.kr·쇼핑몰 접속이 막혀 확인 못 한 것)

- [ ] 식품안전나라 C005·C002 실응답 필드명이 `mfds.js` FIELDS와 같은지 (키 발급 후 1회 호출)
- [ ] 나이별 나트륨·에너지 수치를 2020 KDRIs 원문과 대조 (`core/nutrition.js` AGE_BANDS)
- [ ] 고열량·저영양 판별 기준(간식·식사대용)을 현행 식약처 고시 원문과 대조 — 지금은 간식 기준만 구현
- [ ] 알레르기 표시대상 목록이 현행 「식품 등의 표시기준」과 같은지 (보도마다 19~22종으로 셈이 다름)
- [ ] 출처 링크 전수 확인 (`core/additives.js` SOURCES, `core/score.js` NUTRITION_SOURCES)
- [ ] 쿠팡·네이버 스마트스토어·컬리·SSG·11번가 실제 상세 페이지에서 고시표 읽기 확인
      (가짜 쿠팡 페이지로는 확인함 — 늦게 그려지는 표까지 읽음)
- [ ] 라벨 사진 전사 품질: 실제 포장 사진 30장 정도로 원재료 누락률 측정

## 리스크와 원칙

- **브랜드 평가**: 판정마다 근거와 출처를 공개하고, 제조사 정정 요청 창구를 둔다. 사실(원재료·수치)만으로 판단.
- **의료 표방 금지**: 진단·예방·치료 문구 금지. 화면 하단 고지 유지.
- **제휴**: 쿠팡파트너스 등 제휴 링크를 쓰면 공정위 「추천·보증 심사지침」에 따라 수수료 고지를 링크 옆에 둔다.
  점수·순위는 제휴와 분리 (`malls.js`의 `affiliate` 표시, 정렬 키는 점수뿐). 이 저장소엔 이미 쿠팡 Open API 서명 코드(`src/feed/coupang.js`)가 있어 재사용 가능.
- **아이 건강정보**: 알레르기는 민감정보에 가깝다. 기기에만 저장(PWA localStorage, 확장 storage.local). 서버는 요청마다 받고 저장하지 않음.
- **쇼핑몰 페이지 읽기**: 확장은 사용자가 연 페이지만 읽고 몰 서버를 따로 긁지 않는다.
