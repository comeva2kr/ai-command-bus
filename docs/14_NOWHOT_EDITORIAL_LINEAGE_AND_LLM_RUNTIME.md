## 주장 계보

각 이슈는 정규화 URL 또는 출처·제목으로 만든 안정 `evidenceId`와 다음 메타데이터를
보존한다.

- 원문 제목, 출처 ID·표시명·역할
- 운영 그룹과 그 판단 근거, 전재 그룹
- 원시 피드 관측 수와 중복을 접은 운영그룹 수
- 정규화 URL, 발행 시각, 최초 관측 시각
- 대표·보강·관련 관측 역할

여섯 문장은 다음 basis를 섞지 않는다.

| 문장 | basis |
|---|---|
| `headline`, `whatHappened` | `source_titles` |
| `whyImportant` | `editorial_policy` |
| `whyHot` | `measured_signal` |
| `whyForYou` | `explicit_selection` |
| `watchNext` | `editorial_watch` |

주제·카테고리·출처 근거·측정값을 SHA-256 `evidenceHash`로 묶는다. 근거 ID 누락,
알 수 없는 근거 참조, 잘못된 URL, 해시 불일치, 측정 계보 불일치는 발행 계보 HOLD다.

## 선택형 LLM 런타임

기본값은 OFF다. `NOWHOT_LOCAL_EDITORIAL_LLM=1`과 API 키가 함께 있을 때만 새 근거
판본을 편집한다.

1. 사용자 ID가 없는 공유 판본에서 계보 통과 이슈만 모은다.
2. 최대 24개를 한 편집 요청으로 보낸다.
3. 편집기는 제목·근거 ID 안에서 세 필드만 작성한다.
4. 별도 검증기가 각 필드의 근거 지원 여부를 판정한다.
5. 로컬 규칙과 검증을 모두 통과한 필드만 적용한다.
6. 검증 완료 결과를 `evidenceHash`로 캐시한다.
7. 나머지 이슈와 모든 실패 경로는 기존 결정론적 문장을 그대로 제공한다.

판본 신규 근거가 없으면 호출 0회, 캐시 미스가 있으면 판본당 최대 2회다. 모델 입력에
원문 전문, URL, 사용자 ID를 싣지 않는다. 실제 입력·출력 토큰은 기존 비용 원장과
판본 영수증에 함께 기록한다.

`030`은 LLM 호출·계보 형식을 바꾸지 않는다. 기계 게이트와 근접중복 제거 뒤 남은
클러스터만 편집 입력 자격을 가지며, 분야별 퍼널은 그 이전 손실과 최종 반복 보류를

## 단발 canary 실행 계약

스테이징 전체의 LLM 플래그를 켜지 않고 `tools/editorial-llm-canary.mjs`가 현재 로컬
판본에서 서로 다른 분야 최대 3개 이슈만 고른다. 대상 서버는 HTTP loopback만 허용하고
편집 1회·검증 1회, 합계 최대 2회로 닫는다. 원문 전문·URL·사용자 ID는 보내지 않는다.

키 없이 실행하는 기본 명령은 계획만 출력하며 외부 호출은 0회다.

```bash
npm run editorial:canary -- --base http://127.0.0.1:4100 \
  --categories business,news,realestate --max-issues 3
```

실제 호출은 `ANTHROPIC_API_KEY`가 현재 셸에 이미 있고 David가 승인한 경우에만 아래
별도 승인 플래그와 `--execute`를 함께 요구한다. 하나라도 빠지면 호출 전에 실패한다.

```bash
NOWHOT_LLM_CANARY_APPROVED=1 npm run editorial:canary -- --execute \
  --base http://127.0.0.1:4100 --categories business,news,realestate --max-issues 3
```

2026-08-11 dry-run은 16개 계보 통과 이슈 중 경제·뉴스·부동산 각 1개, 총 3개를
선정했고 외부 호출 0회였다. 실제 출력·토큰·검증 거부율은 키와 승인 뒤 생성되는
`NOWHOT-EDITORIAL-LLM-CANARY-001` 영수증 전까지 미관측이다. 영수증이 생성되면 로컬
증거 API가 최대 60초 안에 읽어 관리자 개발관리의 호출·적용·거부·토큰 상태를 갱신한다.
