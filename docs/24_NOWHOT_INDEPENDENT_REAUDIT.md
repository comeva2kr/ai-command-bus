## 현재 실제 모습

2026-08-11 저장판을 로컬 API로 직접 요청했다.

| 판 | 저장 이슈 | reader PASS | 응답 |
|---|---:|---:|---:|
| 모닝 | 42 | 41/42 | HTTP 200 |
| 런치 | 42 | 37/42 | HTTP 200 |
| 이브닝 | 42 | 37/42 | HTTP 200 |

14개 분야 이브닝 응답은 42건, `publishable:true`였지만 분야 충족은 `13/14`,
부족 분야는 부동산이었고 reader HOLD 5건이 본문에 포함됐다. 활성 검수 패킷은
`reader_copy_hold`, 사람 완료 0건, LLM 호출 0회다. 모닝 응답과 활성 검수
패킷을 비교하면 독자 7필드 중 `change` 값이 `42/42` 달랐다.

즉 현재 `publishable`은 독자 품질 PASS가 아니라 최소 이슈 수 조건이다. 품질
판정은 존재하지만 `/api/today`의 실제 응답 권한자가 아니다.

## 직접 재현

1. reader HOLD 5건과 분야 부족이 있는 이브닝 판이 HTTP 200으로 제공됐다.
2. 실제 모닝 응답의 `change`가 활성 검수 패킷과 42행 모두 달랐다.
3. `whatHappened`가 있는 이슈의 `paragraph`만 바꾸면 `lineage_pass`가 유지됐다.
4. 구조화 근거가 없는 임의 `whyImportant`와 변화 문장이 `reader_copy_pass`할 수 있었다.
5. 서로 다른 갤럭시 공개 사건이 같은 사건으로, 같은 호르무즈 사건 변주가 새 사건으로 판정됐다.
6. 관련기사의 임상시험 키워드가 무관한 문화행사의 중요성·다음 확인을 바꿔도 PASS했다.
7. 이슈 한 건에 `business`, `realestate`를 함께 넣으면 두 분야 최소 깊이를 모두 채웠다.
8. `like` 뒤 다른 신호를 쌓고 평가를 삭제하면 대조 사용자와 다른 특징 벡터와 `feedbackCount=1`이 남았다.

## 앞 수리와의 관계

`NOWHOT-B6-COUNTEREXAMPLE-REPAIR-001`의 네 회귀는 계속 GREEN이다.

- 현재 주장 텍스트 변조 재해시
- verifier 없는 캐시 miss 처리
- 변화 원자료 누락 시 reader HOLD
- 명시 평가 즉시 삭제와 직접 특징 기여 역연산

이번 재검수는 그 결과를 취소하지 않는다. 더 넓은 입력과 실제 서빙 경로에서
별도 공백을 확인한 append-only 후속 판정이다. 재검수 시작 시 전체 회귀는
`1107/1107 PASS`였다. 영수증 반영 뒤 정본·관리자 집중 검증은 `21/21 PASS`,
전체 회귀는 다시 `1107/1107 PASS`, diff 공백 검사는 PASS였지만 제품 판정은
`BLOCK`이다.

## 다음 한 단계

다음 작업은 `B6-SERVEABLE-EDITION-REPAIR` 하나로 제한한다.

1. `editionForRequest()` 직후 실제 반환할 응답 그대로 검수 패킷을 만든다.
2. 그 packet의 reader 품질 PASS와 선택 분야 충족을 함께 확인한다.
3. 실패하면 같은 선택 조합과 reader 지문의 마지막 검증판만 제공한다.
4. 검증판이 없으면 품질 미달 현재판을 HTTP 200 본문으로 보내지 않고 409로 닫는다.
5. HOLD, 분야 부족, 응답·패킷 불일치 세 반례를 라우트 회귀로 먼저 고정한다.

이 수리 뒤 독자가 보게 될 모습은 “검수에서 본 문장과 실제 화면의 문장이 같은
판”이다. 현재판이 기준에 못 미치면 검증된 직전판이 표시되고, 그것도 없으면
새 브리핑이 준비되지 않았다는 명시 상태가 나온다. 품질 미달 42건을 정상판처럼
보여주지는 않는다.
