공급자나 단일 가중치에 종속되지 않는다.

## 제품 계약

> 사용자가 명시적으로 선택한 관심 카테고리의 국내외 뉴스·정보·유머·지식을
> 신뢰할 수 있는 공개 근거와 실제 확산 신호로 선별하고, 아침·낮·저녁 하루 세
> 판의 개인 브리핑으로 제공한다.

- 선택 카테고리가 일반 지면의 주인이다.
- 한 카테고리를 선택하면 그 분야를 깊게 제공한다.
- 여러 카테고리를 선택하면 유효 후보량에 비례해 판본의 내용과 길이가 늘어난다.
- 고정된 총 아이템 수나 `상위 5개만` 계약을 두지 않는다.
- 품질 기준을 통과한 후보가 적으면 억지로 채우지 않는다.
- 선택하지 않은 카테고리를 탐색 목적으로 자동 혼합하지 않는다.
- 선택 밖의 국가적·세계적 필수 사건은 `전체 필수` 레인에 분리해 이유를 표시한다.
- 한 판본은 한 연속 페이지에서 완결하며 필수 정보를 `더보기` 뒤에 숨기지 않는다.

## 핵심 원리

1. 코드는 반응과 출처를 측정한다.
2. LLM은 근거 묶음 안에서 의미를 판단하고 편집한다.
3. 검증 게이트는 수치·문장·출처의 일치를 확인한다.
4. 사용자별 조립은 명시적 선택을 기준으로 결정론적으로 수행한다.
5. LLM이 측정값, 출처 신뢰도, 사실을 추측하지 못하게 한다.
6. 클릭 최대화보다 중요한 정보의 누락 최소화를 우선한다.

### 현재 사건 결합 경계 · v12

한 문단에 여러 글의 사실을 섞는 사건 결합은 정규화 제목이 완전히 같거나, 추적
파라미터를 제거한 canonical 원문 URL이 같을 때만 허용한다. 출처 기본 태그, 태그
겹침 수, 부분 제목 유사도, 같은 카테고리, 같은 발행사는 결합 근거로 쓰지 않는다.
변주 제목은 별도 이슈로 보존하되 발행 이슈 선택 단계에서만 근접 중복 노출을
억제한다. 따라서 근접 중복 오판이 발생해도 두 원문의 사실이 한 문단으로 섞이지 않는다.

2026-08-11 로컬 전체 분야 재생에서는 후보 240건이 사건 239건으로 정리됐다. 복수
멤버인 유일한 사건은 정규화 제목이 완전히 같은 과학 기사 2건이었고, 발행 42건의
복수 URL 문단은 0건이었다. 이전 `v11`에서 합쳐졌던 `lost we`, `Ultra With` 두
묶음은 서로 다른 사건으로 분리했다. 이 기계 영수증은 사람의 사건 동일성 판정을
대신하지 않는다.

### 현재 공급·출처 균형 경계 · v13

`v12`의 고정밀 사건 결합은 그대로 유지하고 판본 키만 `v13:`으로 올렸다. 게임
분야에는 일반 독자가 읽을 수 있는 국내 `게임메카`와 국외 `PC Gamer` 공식 RSS를
추가했다. 둘 다 2026-08-11 실제 응답·파싱·robots 경계를 확인했으며 제목·요약·원문
링크만 편집 재료로 사용한다. 인벤 핫벤은 정확하지만 매니악한 인게임 글 중심이라
`mainFeed:false`를 유지하고, 루리웹 300143은 유머판이라는 분류도 바꾸지 않는다.

소스 상한 때문에 목표 지면을 못 채울 때는 상한을 무작정 풀어 원래 순위대로 넣지
않고, 현재 가장 적게 뽑힌 출처의 다음 고순위 이슈를 순환 선택한다. 현재 풀 기계
재생에서 게임 단독판은 25후보·14이슈, 일반 뉴스 두 곳은 7/6건으로 갈렸고 전 분야
판은 42이슈·14/14 분야 충족이었다. 이는 정시 판이나 사람 품질 PASS가 아니다.

## 소스 신뢰 레지스트리

출처 신뢰는 LLM의 인상이나 정치 성향 추정으로 만들지 않는다. 아래의 관측 가능한
필드를 레지스트리에 보존하고 카테고리별 자격·가중치 근거로 사용한다.

| 필드 | 역할 |
|---|---|
| `sourceId` | 출처 안정 ID |
| `ownershipGroup` | 동일 소유·계열 매체 중복 계산 방지 |
| `syndicationGroup` | 통신사 전재·복제 기사 독립 출처 오인 방지 |
| `sourceRole` | 공식·1차·전문·일반·커뮤니티·집계 구분 |
| `authorityByCategory` | 해당 분야 전문성의 근거와 관측일 |
| `originalityEvidence` | 원출처·직접 취재·공식 발표 여부 |
| `correctionEvidence` | 정정 공개 방식과 확인 가능한 이력 |
| `availableSignals` | 추천·댓글·조회·공유 등 실제 제공 수치 |
| `engagementReliability` | 봇·중복·순위 편향을 포함한 수치 사용 가능 범위 |
| `observedAt` | 마지막 직접 확인 시각 |

`신뢰도 높음` 같은 표시를 공개하려면 위 근거와 판정 방법을 함께 공개해야 한다.
근거 없는 단일 매체 신뢰 점수는 만들지 않는다.

## LLM 역할 계약

LLM은 편집자이며 측정기나 단독 발행자가 아니다.

| 역할 | 입력 | 출력 |
|---|---|---|
| `classifier` | 제목·공개 메타데이터·제한된 발췌·신호 | 카테고리·주제·클러스터 후보 |
| `judge` | 클러스터 근거 묶음·카테고리 정책 | 중요 이유·영향 대상·불확실성 제안 |
| `editor` | 검증 가능한 근거와 점수 축 | 한국어 브리핑 구조화 초안 |
| `verifier` | 초안의 주장 단위와 출처 매핑 | 지원·충돌·미지원 판정 |

### 금지

- LLM이 댓글·클릭·공유·출처 수를 만들어 내는 것
- 출처 신뢰도를 모델의 사전지식이나 인상만으로 정하는 것
- 근거에 없는 인과관계·의도·미래 결과를 단정하는 것
- 검증 실패 문장을 표현만 바꿔 다시 통과시키는 것
- 사용자마다 전체 브리핑을 새로 생성하는 것
- 모델 응답만으로 발행 완료를 선언하는 것

## 사용자별 조립

LLM이 검증된 사건 설명을 사용자마다 다시 쓰지 않는다. 세 판의 공용 `판본 재고`를
먼저 만들고 아래 규칙으로 일반 코드가 사용자 페이지를 조립한다.

1. 명시적으로 선택한 카테고리를 일반 지면의 후보 풀로 사용한다.
2. 선택한 카테고리 수와 품질 통과 후보량에 비례해 페이지 길이를 늘린다.
3. 한 카테고리만 선택하면 해당 분야의 유효 후보를 충분히 제공한다.
4. 여러 카테고리는 억지 균등 배분하지 않고 중요도와 공급량에 따라 배분한다.
5. 행동 학습은 선택 카테고리 안의 세부 순서 조정에 우선 사용한다.
6. 행동만으로 안 고른 카테고리를 조용히 추가하지 않는다.
7. `왜 내게 보임`은 선택 카테고리·세부 주제 근거를 표시한다.

## 비용·속도·캐시

- 모든 원문을 강한 LLM에 바로 보내지 않는다.
- 수치 관문과 임베딩·문자열 유사도로 후보를 먼저 줄인다.
- 저비용 분류 역할과 고품질 최종 편집 역할을 분리한다.
- `clusterId + evidenceHash`가 같으면 편집 결과를 재사용한다.
- 새 신호나 근거가 생긴 클러스터만 증분 처리한다.
- 사용자별 페이지 조립에는 원칙적으로 LLM 호출을 사용하지 않는다.
- 모델별 비용·토큰·지연·검증 실패율을 판본 영수증에 남긴다.
- 비용 한도 초과 시 저품질 자동 생성 대신 검증된 재고와 결정론적 피드를 사용한다.

## 품질 게이트

CTR과 체류시간은 품질의 보조 신호이며 최종 성공 기준이 아니다.

| 지표 | 판정 목적 |
|---|---|
| `criticalMissRate` | 선택 분야의 중대 사건 누락 여부 |
| `selectedCoverageRate` | 선택 카테고리의 유효 후보 포함률 |
| `independentSourceRate` | 독립 출처 교차 확인 수준 |
| `duplicateClusterRate` | 같은 사건 중복 노출 여부 |
| `staleItemRate` | 새 판본의 오래된 정보 혼입 여부 |
| `unsupportedClaimRate` | LLM 문장 중 근거 없는 주장 비율 |
| `materialRepeatRate` | 변화 없는 사건의 판본 간 반복 여부 |
| `detectionLatency` | 중요 사건 발생부터 후보 진입까지 시간 |
| `correctionRate` | 발행 후 수정·철회와 원인 추적 |

목표 수치는 대표 평가 코퍼스와 현재 기준선을 만든 뒤 정한다. 숫자를 먼저 지어내
통과 조건으로 사용하지 않는다.

## B1.5 완료 조건

- 소스 신뢰 레지스트리 스키마와 대표 소스 fixture
- 시계열 신호 스냅샷과 실제 `velocity`·`acceleration` 계산 fixture
- 사건 클러스터·독립 출처·전재 그룹 fixture
- 다섯 점수 축과 카테고리 정책의 판정 예시
- LLM 입력·구조화 출력·주장 검증 스키마
- 아침·낮·저녁 세 판 시뮬레이션과 반복 억제 대조
- 카테고리 1개·여러 개 사용자의 동적 분량 조립 테스트
- 모델 비용·지연·실패 시나리오와 마지막 검증본 폴백
- 주식·부동산·테크·유머 최소 네 분야의 적대적 평가 코퍼스

위 조건은 설계·fixture 준비 게이트다. 코드 존재, 모델 응답, 관리자 화면 노출만으로
운영 준비 완료를 뜻하지 않는다.

결정론적 문장으로 돌아가므로 사람 정답표와 주장 검증 게이트를 우회할 수 없다.
