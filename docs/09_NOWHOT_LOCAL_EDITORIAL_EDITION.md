## 판정

이 작업은 새 제품이 아니다. 이미 운영 중인 지금핫의 수집, 반응 측정, 중복 제거,
카테고리, 설문 개인화, `FeedEngine.briefing`, `buildDigest`, 실시간 피드를 재사용해
첫 화면의 자체 편집 콘텐츠와 분량을 늘린 로컬 고도화 후보다.

사용자가 고른 카테고리가 일반 지면을 소유하고, 한 카테고리만 골라도 유효 공급이
있으면 해당 분야를 충분히 편성한다. 선택 수가 늘면 최대 42개 이슈 범위에서 지면도
늘어난다. 고정 3~5개만 보여 주는 홈으로 축소하지 않는다.

## 동적 후보 계약

`NOWHOT-EDITION-CANDIDATE-CONTRACT-001`은 기존 수집물에서 자체 편집 판본으로
들어간 재료를 재현한다.

1. 이번 판의 이슈 예산과 선택 분야 수에서 후보 안전 상한을 계산한다.
2. 유효 공급이 상한보다 적으면 있는 만큼만 쓰고, 많으면 다양성 관문 뒤에서 자른다.
3. 정규화 URL로 같은 글을 한 번만 남긴다.
4. `utm_*`, `fbclid`, `gclid`, `igshid`, `ref`만 제거하고 게시판 글 번호처럼
   정체성을 가진 쿼리는 보존한다.
5. 선택 분야 최소 후보와 소스 상한을 적용한 뒤 원래 편집 순위를 복원한다.
6. 카테고리, 출처 역할, 운영 소유 그룹, 데스크, 반응·교차보도 수치를 기록한다.
7. 일반 공개 브리핑 API에는 이 로컬 계약과 후보 제목 표본을 추가하지 않는다.

최종 이슈는 선택 분야별 대표 이슈를 현재 분량에 따라 1~3개씩 먼저 확보하고,
남은 자리를 전체 중요도 순으로 채운다. 특정 분야의 유효 재료가 부족하면 있는 만큼만
사용하며 다른 분야의 낮은 중요도 이슈를 억지로 끌어올리지 않는다.

`DEVCHG-NOWHOT-20260811-020`부터 판본 예산은 선택 수에 비례한다. 한 분야 14건,
두 분야 16건, 3~4개는 분야당 7건, 5~8개는 분야당 4건, 9개 이상은 분야당 3건으로
계산하고 발행 상한은 42건이다. 공급이 있는 선택 분야는 전체 중요도 자리를 하나
남긴 뒤 분야당 1~3건을 먼저 확보한다. 서버의 이전 판 교체 후보만 최대 50건까지
생성할 수 있고 최종 발행은 다시 판본 예산으로 잘린다.

운영 그룹 fallback은 출처 중복 계산을 위한 값이지 법적 소유관계나 편집 독립성의
확정값이 아니다. 기계 관측은 후보 수와 관계없이 사람 정답표 PASS로 올리지 않는다.

E1은 두 사람이 같은 자료를 블라인드 표기해 알고리즘을 비교하기 위한 별도 층화

## 현재 판 편집 품질 게이트

현재 판은 고정 건수를 맞추지 않는다. 선택 분야와 유효 공급에서 만들어진 발행 이슈
전체를 동적으로 검사한다. 헤드라인 주제어가 완결되지 않았거나, 출처 근거가 없거나,
관련 보도 묶음을 운영그룹 교차관측처럼 표현하거나, 자체 편집 맥락이 없는 후보는
발행 자리를 차지하지 못하며 다음 순위 후보가 대신 들어간다.

관련 기사 묶음은 `related_coverage_signal`, 지금핫 수집 풀에서 서로 다른 운영그룹을
직접 관측한 경우만 `multiple_feed_observed`로 기록한다. 원시 피드 수는 진단값으로
보존하지만 교차관측 가산점은 운영그룹 수로 계산한다. 같은 발행사의 Google News
중계와 직접 RSS는 두 표로 세지 않는다. 이 둘은 점수, 헤드라인, 본문, 신뢰 라벨에서
같은 사실처럼 표현하지 않는다.

현재 판의 발행 이슈는 익명 ID가 붙은 동적 블라인드 패킷으로 관리자 화면에 투영한다.
기계 게이트 통과는 사람의 포함·제외, 사건 병합, 헤드라인 충실도, 근거 충분성,
카테고리 적합도 판정을 대신하지 않는다. E1은 층·규모·manifest를 함께 동결할 때만
버전 비교에 의미가 있으며 현재 상태는 `not_frozen`이다.
