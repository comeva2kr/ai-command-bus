# NOWHOT-READER-PAYLOAD-FREEZE-QA-001

## 해결한 문제

직전 목적 적합성 검수에서는 비저장 판의 검수 패킷 42행이 `reader: null`인
상태에서도 정본 구조 검사만으로 `42/42 PASS`가 가능했다. 독자 화면은 응답 시점에
별도 문장을 만들었으므로 검수 대상과 실제 표시 문장이 달랐다.

변경 뒤에는 다음 순서를 강제한다.

1. 독자 화면에 표시할 `headline`, `summary`, `whyImportant`, `whyNow`, `change`,
   `watchNext`, `confidenceLabel`을 먼저 생성한다.
2. 일곱 필드와 행별 `readerGate`를 검수 패킷에 함께 동결한다.
3. 필수 필드, 길이, 한국어 가독성, 내부 용어, 사건 구체성, 근거 있는 `whyNow`,
   구체적 `watchNext`를 같은 동결 문장으로 검사한다.
4. 행 검사를 통과해도 `whyImportant`, `whyNow`, `watchNext`의 동일 문장 반복이
   판 행 수의 15%를 넘으면 판 전체를 HOLD한다.
5. 사람 검수 준비 상태와 기계·전체 품질 상태를 분리한다. 사람 입력 화면이
   준비됐다는 이유로 기계 HOLD가 PASS로 바뀌지 않는다.

구체적인 다음 관측점이 없는 `watchNext`는 상용구를 만들지 않고 비워 둔다. 오늘
화면은 빈 `watchNext` 행을 렌더링하지 않는다.
