## 2. `adfit.mobileUnit = null`은 의도된 설계 (버그 아님)

라이브 `GET /api/config` → `adfit: {"mobileUnit": null}` (build `di2Qvfim`).
처음엔 유실을 의심했으나 **근거가 코드 주석에 명시돼 있음.**

`src/feed/server.js:2152-2155`

```js
// 심사 통과 전에는 슬롯을 아예 그리지 않는다 (2026-08-04).
// 실측: 애드핏 SDK는 심사 보류 상태에서 onfail을 부르지 않는다 — 아무것도
// 안 보여주면서 "채웠다"로 처리. ins 안 safeframe iframe이 크로스오리진이라
// 채워졌는지 빈 칸인지 구분 불가, 워터폴 패스백으로도 안 잡힘. 결과 169px
// 빈 칸이 지면만 먹고 수익 0 (David 실기기 제보 "하나도 안 보이는데").
// 그 자리를 쿠팡이 대신 받는다. 승인되면 ADFIT_ENABLED=1로 켠다.
const adfitOn = process.env.ADFIT_ENABLED === "1" && process.env.ADFIT_UNIT_MOBILE;
const adfit = { mobileUnit: adfitOn ? process.env.ADFIT_UNIT_MOBILE : null };
```

관련 커밋 `c9c8d24 애드핏은 승인 전까지 지면을 내주지 않는다`.

**→ 복구 작업 불필요.** 승인 시 VM `deploy/.env`에
`ADFIT_ENABLED=1` + `ADFIT_UNIT_MOBILE=DAN-ay04FFmKGxgYuWeQ` → push 자동배포.
패스백 배선(`data-ad-onfail` → 쿠팡) 이미 살아 있음.
검증 훅 존재: `tools/preflight.mjs:89`가 `adfit.mobileUnit` 확인.

**애드센스는 정상**: `adsbygoogle` 1건, `/ads.txt`에 `google.com, pub-9799388228968567, DIRECT, f08c47fec0942fa0`, 사이트 200.
