## P0 구조 결함

### AR-P0-01. 주장·출처 계보 계약 부재

`sourceEvidence` 목록만으로는 어떤 문장이 어느 원문의 어느 구절에 의해 지지되거나
충돌하는지 재현할 수 없다. `claimId → sourceId → 원문 구절 → 지지/충돌 → observedAt
→ verifierVersion`을 고정하고, 미지원·충돌·불명은 자동 발행하지 않아야 한다.

### AR-P0-02. 클러스터 정답과 되돌리기 계약 부재

같은 사건, 후속, 분석, 반응, 전재를 구분하는 관계형 정답과 병합·분할·대표 보도
선택 이유가 없다. 오병합은 여러 사건을 하나의 사실처럼 만들 수 있으므로 버전,
수동 수정, 되돌리기, 평가 코퍼스가 B2보다 먼저 필요하다.

### AR-P0-03. 초기 사용자·분야·세 판·읽기 예산 미검증

모든 분야, 동적 무제한 분량, 세 번의 완결판을 동시에 약속하면 공급 부족과 반복,
모바일 과밀을 구분할 수 없다. 검수 당시에는 사용자 집단 하나와 테크 한 분야를
권고했으나, 현재 첫 분야는 후속 David 결정에 따라 투자자용 시장·정책으로 바뀌었다.
아침 완결판과 낮·저녁 변화판을 세 완결판과 비교하는 실험 구조는 유지한다.

### AR-P0-04. 원자 발행·SLO·비용·인간 이관 부재

수집부터 발행까지의 run·snapshot·model·prompt·verifier·edition 버전, 멱등성 키,
검증 완료 판본의 원자 전환, 재처리·DLQ, 마지막 검증본 폴백, 지연·비용 상한과
담당자 호출 조건이 없다. 이 상태에서 네 개 LLM 역할을 먼저 구현하면 실패 원인과
비용을 추적하기 어렵다.

## 유지·단순화

유지한다:

- 명시적으로 선택한 관심사가 일반 지면을 소유한다.
- 국내외 사건을 클러스터로 묶고 사실·해석·불확실성을 분리한다.
- 장애 때 마지막 검증 판본을 계속 제공하고 변경·정정 이력을 남긴다.

단순화한다:

- 검수 당시 첫 분야 권고는 테크였으며, 현재는 초기 사용자 하나와 시장·정책 한 분야로 제한한다.
- LLM은 생성자와 독립 검증자 두 단계로 시작하고 측정·발행은 결정론적 코드가 맡는다.
- `51→85` 설계 점수와 단일 신뢰 점수는 승인 지표로 쓰지 않는다.

### E1. 클러스터·주장 근거 골든팩

최근 입력을 분야·근거 유형·출처 역할·변화 상태로 층화하고, 파일럿 불일치율과 목표
정밀도·검수 예산을 본 뒤 규모와 manifest를 동결한다. 두 사람이 같은 manifest를
블라인드로 사건 관계, 원출처, 대표 보도, 주장별 원문 근거까지 표시한다. 이 한 팩으로
클러스터, 출처 독립성, LLM 검증을 같이 평가한다. 후보 문턱은 pair-F1 0.92 이상,
중대 오병합 0.5% 이하, 주장 인용 100%, 검증기 오통과 1% 이하이며 실측 뒤 확정한다.

### E2. 390px 세 판 정적 A/B

사용자 12명에게 같은 골든팩으로 `세 완결판`과 `아침 완결판 + 낮·저녁 변화판`을
비교한다. 첫 화면에서 최우선 사건·판본 상태·출처 진입이 보이는지, 3일 재방문,
중복 체감, 읽기 시간, 누락 인식을 측정한다. 정적 HTML로 검증해 제품 엔진은 만들지 않는다.

### E3. 7일 그림자 재생과 장애 주입

E1에서 동결한 같은 manifest를 7일 동안 재생하면서 수집·모델·검증·캐시에 20% 실패를 주입한다.
결정론적 출력 해시, 마지막 검증판 보존, p95 지연, 판본별 비용, 누락·중복·무변화
반복을 기록한다. 후보 문턱은 중요 사건 탐지 p95 15분 이하, 누락 5% 이하,
중복 2% 이하, 무변화 반복 5% 이하이며 기준선 뒤 승인한다.
