# NOWHOT-B6-FEEDBACK-ROLLBACK-REPAIR-001

## 판정

- 변경 ID: `DEVCHG-NOWHOT-20260811-061`
- 환경: 로컬 복제본
- 범위: 명시 평가 뒤 묵시 신호가 끼어도 평가 해제 상태를 정확히 원복
- 결과: `LOCAL REPAIR PASS WITH LIMITS`
- 현재 허용: 다음 개인화 효용 오프라인 평가
- 현재 금지: 운영 반영, 실제 이용자 전환, 새 소스·발행량·LLM 범위 확대

## 확인된 결함

같은 설문 상태의 두 사용자를 만들었다. 한 사용자는 `좋아요 → 완독 → 평가 해제`,
대조 사용자는 `완독`만 수행했다. 평가가 저장 목록에서는 사라졌지만 기존 구조는
좋아요 기여분까지 묵시 신호 때 감쇠한 뒤 원래 크기를 빼서 특징 벡터에 잔차를
남겼다. `feedbackCount`도 `1`로 남았고 이 상태는 JSON 재시작 뒤에도 유지됐다.

즉 평가 해제는 화면 상태만 지웠고 추천 특징과 개인화 확신은 완전히 지우지 못했다.

## 수리 계약

`NOWHOT-FEEDBACK-OVERLAY-CONTRACT-001` v1을 적용했다.

1. 설문·이력·열람·체류·완독·건너뛰기는 `preferenceBase`만 갱신한다.
2. 현재 남아 있는 좋아요·싫어요는 최소 아이템 특징과 함께 `ratings`에 저장한다.
3. 독자에게 쓰는 `preferences`는 base 위에 현재 ratings만 결정적으로 다시 투영한다.
4. 평가 해제는 rating을 삭제하고 재투영한다. 다른 신호를 역산하지 않는다.
5. `feedbackBaseCount + 활성 평가 수`로 `feedbackCount`를 다시 계산한다.

이벤트를 계속 저장해 재생하는 방식은 쓰지 않았다. 사용자별 무한 행동 원장은 0건이고,
현재 활성 평가의 작은 특징 스냅샷만 보존한다.

## RED → GREEN

| 검사 | RED | GREEN |
|---|---:|---:|
| 즉시 평가 해제 | 직접 특징 기여 역산만 통과 | PASS |
| 평가→완독→해제와 완독만 한 대조 사용자 | 특징 벡터·확신 수 불일치 | PASS |
| JSON 저장·재시작 뒤 대조 | 잘못된 상태 유지 | PASS |
| 피드 전체 회귀 | 미실행 | `179/179 PASS` |
| 저장소 전체 회귀 | 미실행 | `1,126/1,126 PASS` |

집중 회귀는 평가 저장, 즉시 해제, 중간 신호 뒤 해제, 묵시 신호를 묶어 `4/4 PASS`다.
외부 LLM 호출은 0회이고 운영 반영도 0건이다.

## 로컬 데이터 이행 대조

2026-08-11 로컬 개발 서버가 쓰는 복제 JSON을 읽기 전용으로 검사했다.

- 사용자: 365명
- 활성 평가가 있는 사용자: 0명
- 추정 없이 v2 base로 이행 가능한 사용자: 365명
- `feedbackBaseCount + ratings 수 = feedbackCount`: 365/365 일치

따라서 현재 로컬 복제본은 기존 명시 평가 효과를 추정하거나 버리지 않고 전원 이행할
수 있다. 이 수치는 운영 파일의 현재 상태를 증명하지 않는다. 운영 승격 직전 같은 감사를
다시 수행해야 한다.

## 바뀐 모습

- 좋아요 뒤 기사를 완독하고 좋아요를 취소해도 완독으로 배운 취향은 남는다.
- 취소한 좋아요의 카테고리·태그·출처 가중치는 남지 않는다.
- 평가 수와 개인화 확신 수가 함께 내려간다.
- 서버가 재시작돼도 위 세 상태가 대조 사용자와 같다.
