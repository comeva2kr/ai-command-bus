- 요구사항: `NH54-EDITORIAL-REVIEW-DESK`
- 변경: `DEVCHG-NOWHOT-20260811-048`
- 환경: 로컬 복제본
- 운영 반영: 없음
- 현재 상태: 로컬 코드·브라우저 QA 통과, 실제 2인 검수 미완료

## 목적

관리자 원장 표에서 기계 필드를 훑는 대신, 독자가 실제로 읽는 한 건의 제목·리드·중요성·
변화·다음 확인과 원문 근거를 같은 화면에서 읽고 판정한다. 이 데스크는 새 검수 체계를
만들지 않는다. 기존 불변 검수 패킷과 검수자별 원장 위에 독자 화면 기준 작업면을 얹는다.

## 화면 계약

`/admin/editorial-desk`는 관리자 토큰이 필요한 로컬 전용 화면이며 `noindex,nofollow`다.
데스크톱은 다음 세 영역을 고정한다.

1. 왼쪽: 전체·미완료·보류 필터와 이슈 목록, 현재 진행률
2. 가운데: 독자용 제목·요약·중요성·지금 나온 이유·지난 브리핑 이후 변화·다음 확인,
   원문 링크, 접을 수 있는 저장 원본 대조
3. 오른쪽: 현재 검수자의 다섯 판정, 메모, 이전·다음·다음 미완료 이동

모바일에서는 이슈 목록을 가로 탐색으로 바꾸고 기사와 판정 영역을 세로로 이어 붙인다.
카드 안에 카드를 중첩하지 않고, 가장 중요한 작업인 기사 읽기와 판정을 한 흐름으로 둔다.

## 다섯 판정

| 필드 | 사용자 질문 |
|---|---|
| `include` | 지금 이 브리핑에 실을 가치가 있는가? |
| `clusterCorrect` | 하나의 사건으로 올바르게 묶였는가? |
| `headlineFaithful` | 제목과 요약이 근거에 맞고 자연스러운가? |
| `evidenceSufficient` | 표시된 설명을 뒷받침할 근거가 충분한가? |
| `categoryFit` | 선택한 분야에서 볼 만한 내용인가? |

다섯 필드가 모두 참 또는 거짓으로 정해져야 그 행을 완료로 센다. 하나라도 거짓이면
보류 행이다. 미판정은 통과도 보류도 아니다.

## 독립성·편향 방지

- `reviewer-a`와 `reviewer-b`는 현재 좌석의 원장만 읽고 쓴다.
- 두 사람이 전 행을 끝내기 전에는 상대 답·메모·일치율을 공개하지 않는다.
- 기계 게이트 결과는 입력 화면과 전용 API 행에서 숨긴다.
- 내부 개인화 감사 필드 `whyForYou`는 숨긴다.
- 저장 원본과 검수 패킷 행은 수정하지 않는다.
- 좌석 전환은 계정 본인확인이 아니다. 실제 서로 다른 사람 배정은 별도 증거가 필요하다.

## 읽기·저장 경계

읽기는 `GET /api/admin/editorial-desk?reviewerId=reviewer-a|reviewer-b`가 담당한다. 응답은
독자용 문장, 저장 원본 비교, 근거 링크, 현재 좌석 주석만 포함한다.

입력은 기존 `POST /api/admin/editorial-review`에 450ms 지연 자동 저장한다. `packetId`,
`editionId`, `reviewerId`, 전체 행 주석을 함께 보내며 서버의 기존 패킷·검수자·중복 행·
필드 검증을 그대로 사용한다. 저장 실패는 화면에 남기고 성공으로 위장하지 않는다.
