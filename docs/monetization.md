## 딥리서치 근거 요약 (2026-07-24 — 4축 병렬 리서치, 출처 하단)

**핵심 통찰: 우리는 "아웃링크" 서비스라 유저를 밖으로 내보낸다. 그래서 체류시간 기반 배너광고는 구조적으로 불리하고, "클릭·전환을 수익화"하는 모델(제휴 CPS, CPC 네이티브)이 유리하다.** 이 가설은 리서치로 검증됨 — 배너 CPC는 클릭당 20~30원인데 제휴는 전환당 수천~수만원. 그리고 우리의 개인화(취향 벡터)가 제휴 전환율을 끌어올린다(개인화 추천이 무작위 대비 전환율 유의미 상승 — 벤더 수치는 과장 감안해도 방향은 확실).

## Problem Statement

내 취향 피드는 기능적으로 완성(테스트 58개 통과)되어 배포까지 마쳤지만 수익 구조가 없다. 서버·번역 API·유료 플랜(디스크 영속화) 등 운영 비용은 사용자 증가와 함께 커지는 반면 수입은 0이므로, 지속 운영이 불가능하다. 최우선 목표가 "합법 범위 내 수익화 가능한 프로덕트"인 만큼, 트래픽이 작을 때부터 작동하는 수익원을 먼저 붙이고 규모에 따라 층을 쌓는 설계가 필요하다.

## Goals

1. **소규모 트래픽에서도 첫 수익 발생** — 출시 후 30일 내 첫 제휴 수수료/광고 수익 기록 (금액 무관, 파이프라인 검증이 목적).
2. **취향 데이터를 수익 전환** — 추천엔진의 1st-party 취향 벡터로 제휴 카드 CTR ≥ 일반 배너 대비 2배 (자체 A/B 측정).
3. **비용 자립** — MAU 1천 시점에 월 인프라 비용(Render 유료 플랜 + 번역 API) 100% 커버.
4. **법적 안전 유지** — 광고·제휴 도입 후에도 legal.md 원칙(아웃링크·발췌 캡·본문 미복제) 위반 0건, 표시광고법 고지 100% 적용.

## Non-Goals

- **성인(19금) 영역 수익화** — 광고 네트워크 정책 위반 리스크가 크고 계정 정지 시 전체 수익원이 죽는다. 19금 뷰에는 광고·제휴 카드를 서빙하지 않는다.
- **콘텐츠 유료화(페이월)** — 아웃링크 모델 특성상 콘텐츠는 원저작자 것. 남의 콘텐츠에 과금하는 순간 법적 안전 모델이 깨진다. 과금 대상은 항상 "우리 기능"이다.
- **유저 데이터 판매/외부 광고 타게팅 제공** — 개인정보보호법 리스크. 취향 벡터는 서버 내부 랭킹에만 쓴다.
- **자체 광고 영업(직판)** — 트래픽 규모가 안 됨. 네트워크 광고로 시작.
- **네이티브 앱 전환** — PWA 유지 (앱스토어 수수료 30% 회피가 오히려 수익 이점).

## 수익원 우선순위

### P0 — 제휴 커머스 카드 (첫 수익원)

피드 카드 사이에 취향 기반 제휴 카드(쿠팡파트너스 등)를 네이티브 형태로 삽입.

- **왜 첫 번째인가**: 광고 네트워크와 달리 트래픽 심사 문턱이 없고, David가 이미 쿠팡파트너스 운영 경험·계정 보유. 추천엔진의 카테고리/태그 가중치를 그대로 상품 카테고리 매핑에 재사용 가능.
- **동작**: `engine`이 N개 피드 아이템마다 1개 제휴 슬롯 삽입(빈도 설정값). 유저 취향 벡터 상위 카테고리 → 제휴 상품 카테고리 매핑. 카드에는 `광고`/`파트너스` 라벨 + "이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다" 고지.
- **수용 기준**:
  - [ ] 제휴 카드는 일반 아이템과 명확히 구분되는 라벨 표시 (표시광고법)
  - [ ] 19금 뷰·미성년 추정 세션에는 미노출
  - [ ] 카드 클릭도 아웃링크 (제휴 링크로 이동, 프레이밍 없음)
  - [ ] 슬롯 빈도는 env로 조절 가능, 0이면 완전 비활성
  - [ ] 제휴 카드는 추천 학습 신호(skip/dwell)에서 제외 — 오학습 방지
  - [ ] **(라운드1 검수 #10, 실연동 acceptance)** `opts.productFeed`로 실제 쿠팡파트너스 상품 피드를 연동할 때: 카드 `title`이 링크하는 곳은 카테고리/검색 페이지가 아니라 **정확한 상품 상세 URL**이어야 하고, `priceOriginal`(정가)은 **실제로 최근 관측된 가격**이어야 한다(추정치·과거 캐시값·임의 부풀림 금지). `monetize.js`의 `pickAffiliateCandidates` 코드 주석에도 명문화함.
  - [ ] **(라운드2 검수 #1, 실연동 acceptance 추가)** 카드의 매칭 이유(`reason`)는 **실제로 매칭된 카테고리만** 이름을 댈 수 있다 — 유저의 top 카테고리에 해당하는 실제 재고가 없다고 다른 카테고리 재고로 조용히 대체(폴백)하면서 원래 카테고리명을 그대로 문구에 남기는 것은 금지. 매칭 재고가 없으면 그 슬롯은 비운다(강제 채움 금지, 관련성 게이팅과 동일 원칙). `sampleAffiliateCandidates`가 이미 이 기준을 지킨다(`SAMPLE_PRODUCT_TEMPLATES`에 없는 카테고리는 후보 자체를 만들지 않음) — 실연동 `productFeed`도 동일하게 구현해야 한다.
  - [ ] **(라운드2 검수 #2, acceptance)** 정치/종교/성인 카테고리는 어떤 경로(sample/실연동 `productFeed`)로도 광고 후보에 포함될 수 없다 — 유저의 19금/정치/종교 콘텐츠-노출 토글 상태와 **무관하게** 항상 배제. `pickAffiliateCandidates`가 반환 직전에 `BANNED_AD_CATEGORIES`로 강제 필터링.

### P0 — 광고 네트워크 (Kakao AdFit → AdSense)

- **왜 AdFit 먼저**: AdSense는 "짜깁기/스크랩 콘텐츠" 정책 심사에서 어그리게이터가 거절되기 쉽다. AdFit이 국내 심사 문턱이 낮고 모바일 웹 최적화. AdSense는 유저 생성 콘텐츠(내 공간 글·댓글) 비중이 쌓인 뒤 재도전.
- **수용 기준**:
  - [ ] 피드 내 광고 슬롯은 제휴 카드와 합산 빈도 상한 적용 (피드 10개당 광고+제휴 ≤ 2)
  - [ ] 19금 뷰 광고 미서빙
  - [ ] 광고로 인한 스크롤 성능 저하 없음 (lazy load)

### P1 — 프리미엄 구독 ("취향 프리미엄")

무료: 광고 포함 + 기본 기능 전부. 프리미엄(월 2,900~4,900원 밴드 테스트):

- 광고·제휴 카드 제거
- 해외 커뮤니티 **무제한 번역** (번역 API는 실비용 → 무료 티어는 일일 캡, 프리미엄 무제한. 비용-가격 정합)

### 1차지표/가드레일 데이터

`/api/ad-signal`이 노출·클릭을 유저별 카운터(`adStats`)와 원시 이벤트 로그(`adEvents`, userId/itemId/type/variant/timestamp)로 남긴다. 1차지표(세션당 수익 proxy = 클릭수)는 `adminAdStats().clicks`로 바로 집계된다. 가드레일("직후 유기카드 스크롤 지속 여부")은 이 원시 로그를 기존 `user.seen` 타임스탬프와 조인해 분석하는 것을 전제로 설계했다 — **이번 구현은 조인 없이 원시 데이터 수집까지만**이며, 자동 이탈률 계산은 후속 과제로 남겨둔다(과다구현 방지, WRC 효율 원칙).

(3) `tech`/`auto`/`gaming`을 동일 가중치로 학습시킨 유저, `AD_EVERY=9`(페이지당 due 슬롯 1개)로 6페이지 순회 — 카테고리가 `auto, tech, gaming, auto, tech, gaming` 순으로 고르게 로테이션됨(1위 카테고리 고착 없음) — 라운드2 #3 확인. (4) `AD_MAX_PER_SESSION=0` + `AD_EVERY=1`(최대 밀도)로 6페이지 순회 — 누적 광고 0건 — 라운드2 #4 확인.

### 라운드2 검수 수정 (2026-07-25)

수익화 페르소나 검수(라운드2)에서 발견된 결함을 일괄 수정:

- **(치명) 가짜 관련성 문구(거짓 개인화)**: `SAMPLE_PRODUCT_TEMPLATES`는 tech/auto/science/business/gaming/sports/culture/life 8개 카테고리만 커버하는데, taxonomy엔 news/humor/politics도 있다. 이전 코드는 매칭 템플릿이 없으면 `life` 템플릿으로 "조용히" 폴백하면서도 reason 문구엔 실제 카테고리명(예: "정치")을 그대로 박아 "정치 관심사와 관련있어요"라 말하며 실은 청소기(life 상품)를 보여주는 거짓 매칭 주장이 발생했다. `sampleAffiliateCandidates`가 매칭 템플릿이 없는 카테고리는 후보를 아예 만들지 않도록 수정(폴백 제거) — 실제 매칭된 카테고리에 대해서만 reason이 쓰인다. `pickAffiliateCandidates`의 acceptance criteria에도 "실연동 productFeed도 매칭 근거 없이 카테고리명을 주장하면 안 된다"를 명문화.
- **(치명) 정치 게이트 갭**: `engine.js`의 `monetizeAllowed`는 `showTopics`(정치/종교 콘텐츠 노출 **토글**) 상태만 봤다 — 유저가 "정치"를 **관심 카테고리**로만 고르고(토글은 미설정 상태로 둔 채) 취향을 학습시킨 경우, 그 카테고리에 매칭되는 광고 후보가 만들어질 수 있는 경로가 남아 있었다. `monetize.js`에 `BANNED_AD_CATEGORIES`(politics/religion/adult)를 신설해 `pickAffiliateCandidates`가 반환 직전 후보의 **카테고리** 자체로 한 번 더 강제 필터링 — 토글 상태와 무관하게 항상 적용되며, sample/실연동 productFeed 양쪽 경로 모두를 커버하는 단일 체크포인트.
- **(중대) 다중 카테고리 유저 → 항상 1위만**: `injectSlots`는 `poolIdx=0`부터 순차 소비하는데, 기본 설정에서 페이지당 due 슬롯이 보통 1개뿐이라(`AD_EVERY=9`) 매 호출(=매 페이지)마다 `pool[0]`(=취향 1위 카테고리)만 뽑혀, tech/auto/gaming을 골고루 선호하는 유저도 세션 내내 사실상 1위 카테고리 광고만 봤다. `sampleAffiliateCandidates`가 후보 배열의 시작 오프셋을 `opts.seed`(engine.js가 `store.nextAdSeed`로 호출마다 전진시키는 카운터, 템플릿 로테이션에 이미 쓰던 값)로 회전시키도록 수정 — 세션에 걸쳐 top 카테고리들이 고르게 로테이션된다.
- **(중대) `AD_MAX_PER_SESSION=0` = 무제한 버그**: `engine.js`의 세션 캡 체크가 `if (maxPerSession > 0) {...}`였다 — 0이면 이 블록 자체가 스킵돼 캡이 사실상 무제한이 됐다(`AD_EVERY=0`이 "완전 비활성"인 것과 비대칭). 0은 이제 "광고 0개"(즉시 차단)로 명시 처리, 음수는 "무제한"(캡 미적용)으로 명확히 구분.
- **(치명) 광고 배지 색 대비 WCAG AA 미달**: `--ad`(#8b6cf0) 배경 + 흰 11px 굵은 글자의 실측 대비는 3.82:1로 소형 텍스트 AA 기준(4.5:1) 미달 — "이거 광고" 신호가 저시력 유저에게 잘 안 읽혔다. 배지 전용 토큰 `--ad-badge-bg`(#6a4fd1, 흰 글자 대비 5.75:1)를 신설해 `.card-top .ad-badge` 배경만 교체(`--ad` 자체는 다른 곳에서 계속 쓰이므로 값 유지). 🔥화제·좋아요·뉴스 배지와는 여전히 색이 겹치지 않는다.
- **(경미) `ad-why` 칩 배경 대비 약함**: 카드 배경 대비 기존 배경(alpha .14)이 1.19:1로 사실상 안 보여 "칩 형태"로 인지되지 않았다. 배경 alpha `.14→.22`, 테두리 alpha `.32→.5`로 살짝 강화(텍스트 자체는 원래도 읽혔으므로 과하지 않게).
- **(경미) 샘플 고지 위치**: "[샘플]·실제 판매 아님" 고지가 `summary` 문자열 속에 묻혀 있어 (a) `.card p`가 2줄로 클램프되면 잘릴 수 있고 (b) 가격만 훑는 유저는 안 볼 수 있었다. `makeSlotItem`에 `sampleNote` 전용 필드를 신설, `summary`에선 제거하고 `adPriceHtml`(가격 줄)에 바로 붙여 렌더하도록 이동.

## 후킹 카피 (Hook Copy) — 카드 헤드라인 개인화 (Phase A 확장, 2026-07-25)

광고 카드 헤드라인을 딱딱한 상품명("보조배터리 20000mAh")이 아니라 **커뮤니티 후기 말투의 후킹 문장**으로 바꿔 클릭을 유도하는 기능. taste-feed의 "커뮤니티 화제글 사이에 자연스럽게 녹는" 톤에 맞춘다. David 승인 원칙: 위법(허위·과장광고)만 아니면 회색지대는 적극 활용한다.

### 법적 가드레일 (코드에 명문화, `src/feed/monetize.js` 상단 주석)

카드는 이미 배지(`badgeLabel`: "제휴광고"/"제휴광고 · 샘플") + 상단 축약 고지(`disclosureShort`) + 하단 법정 고지 전문(`disclosure`)을 **항상** 렌더한다 — "광고 명시"라는 합법 방패는 후킹 카피 도입으로 절대 제거·약화하지 않는다.

**허용**:
- 제품 실제 특징·장점 어필 (상품 스펙에서 실제로 확인되는 정적 수치·속성만 — 예: "20000mAh", "65W", "저소음")
- 커뮤니티 캐주얼 말투 ("~하는 그거", "이거 하나면 끝")
- 상황 제안 ("출장러 필수템", "여름 필수템")
- 관심 유발 ("요즘 화제인 이유") — 단, 구체적 수치(구매자수·평점 등)를 붙이면 금지 항목 3번에 걸림

**금지** (허위광고/과장광고 = 표시광고법 위반 소지):
1. 검증 가능한 구체적 허위 수치 — 예: "3개월 써보니 배터리 20%도 안 줆"처럼 실사용 기간·정량 변화를 단정하는 문구. 스펙표에 있는 정적 수치는 사실이므로 허용, "사용 후 변화"를 지어내는 수치는 금지.
2. 근거 없는 최상급 — "업계 1위", "최저가", "무조건", "100% 보장" 등.
3. 가짜 리뷰/구매자수 — "OOO명이 구매했어요", "후기 4.9점" 등 실측하지 않은 사회적 증거.

`hasBannedHookClaim(text)`(`monetize.js`, 테스트에서 export)이 2·3번(정량화 가능한 패턴)을 정규식으로 검증하는 최종 방어선이다 — 1번(카피라이팅 판단)까지 정규식으로 완전히 잡을 수는 없어 새 템플릿을 추가하는 사람이 원칙을 직접 지켜야 한다. `test/monetize.test.js`가 큐레이션된 24개 템플릿 전부와 `buildHookCopy` 폴백 출력을 이 체크로 검증한다.

### 정직성 방어선

후킹 헤드라인 아래에 **실제 상품명을 보조 라인으로 항상 노출**한다 — 유저가 "뭔 상품인지"는 헤드라인만 보고도 곧바로 알 수 있게. `sample=true`면 이 보조 라인에 `[샘플]`도 함께 붙는다(예: `· 보조배터리 (20000mAh 고속충전) · [샘플]`). 기존 `sampleNote`("[샘플] 실제 판매 상품 아님", 가격 줄 옆)는 그대로 유지 — 두 표시는 서로 다른 위치의 별개 고지이며 하나가 다른 하나를 대체하지 않는다.

### 알고리즘

**1. 특징 태그 → 후킹 문구 (`src/feed/monetize.js`)**

- `SAMPLE_PRODUCT_TEMPLATES`의 각 항목에 `features`(문자열 배열, 예 `["고속충전","대용량","휴대성"]`)와 `hook`(사람이 직접 쓴 커뮤 후기톤 헤드라인)을 추가했다. 8개 카테고리 × 3개 = 24개 템플릿 전부에 서로 다른 후킹 문구가 있다.
- `makeSlotItem({ hook, productName, title, ... })`: 헤드라인 우선순위는 **`hook` > `title`(하위호환) > `productName`**. 반환 객체의 `title`(카드 h3에 렌더되는 필드)이 이 우선순위로 계산된 헤드라인이 되고, `hook`/`productName` 필드도 원본 그대로 별도 보존된다(클라이언트가 보조 라인 렌더에 `productName`을 직접 쓴다).
- `buildHookCopy(product)`: `product.hook`이 있으면 그대로 반환(사람이 쓴 카피 우선). 없으면 `category`+`features[0]`(topFeature) 조합 규칙으로 폴백 헤드라인을 생성한다 — 4가지 템플릿 문형 중 `(category+name)` 문자열 해시로 결정론적으로 하나를 고른다(같은 입력 → 항상 같은 출력, 테스트 가능). `features`가 아예 없으면 카테고리명만으로, `name`조차 없으면 `null`(만들 재료가 없다는 뜻).
- `sampleAffiliateCandidates`는 이제 `hook: buildHookCopy({ category, name, features, hook })`, `productName: name`을 `makeSlotItem`에 넘긴다.

**2. 실연동(`opts.productFeed`) 확장 경로**: `buildHookCopy`는 샘플 전용 로직이 없다 — 실제 상품의 `title`/`attributes`에서 feature 문자열을 추출해 `{ category, name, features }`로 넘기면 동일한 폴백 규칙이 적용된다. **LLM 기반 카피 생성**(상품 설명 전체를 요약해 더 자연스러운 문장을 만드는 것)은 API 키·비용이 필요한 **향후 업그레이드 대상**으로 명시적으로 남겨둔다 — 지금은 규칙 기반 폴백으로 충분한 품질을 낸다.

**3. 카드 렌더 (`src/feed/public/index.html`)**: `appendAdCard`가 `<h3>`(헤드라인=`item.title`) 바로 아래에 `adProductNameHtml(item)`을 추가로 렌더한다 — `.ad-product-name`(12px, muted) 클래스로 `· {productName}{sample ? " · [샘플]" : ""}` 형태. 배지·상단 축약고지·가격·매칭이유 칩·하단 법정고지는 전부 기존 그대로 유지(회귀 없음).

### 알려진 제약 / 후속 과제

- 실제 쿠팡파트너스 상품 피드 연동은 미구현(약관 원문 확인이 David 확인 대기 — Open Questions 기존 항목 유지). `COUPANG_PARTNER_ID`를 설정해도 `opts.productFeed`를 별도로 넘기지 않으면 여전히 0개 — 반쪽짜리 크레덴셜이 카드를 만들어내지 않도록 의도적으로 막아둠.
- 광고 CPC 네트워크(AdFit, P0 두 번째 항목)는 아직 미착수. `kind: "ad"`를 위한 필드는 마련해뒀지만 후보 생성기는 없음.
- 리텐션 가드레일의 실제 이탈률 계산(로그 조인·집계)은 후속 과제.
- 세션 총량 캡(`AD_MAX_PER_SESSION`)은 로그인 세션 개념이 없는 앱 구조상 "24h 롤링 윈도우"로 근사 구현했다 — 진짜 브라우저 세션 경계가 필요해지면 재검토. 값 의미: 0=완전 비활성, 양수=그 값이 캡, 음수=무제한(라운드2 검수 #4).
- `SAMPLE_PRODUCT_TEMPLATES`가 news/humor/politics 카테고리를 커버하지 않으므로(politics는 애초에 `BANNED_AD_CATEGORIES`로도 배제), 그 카테고리가 top 취향인 유저는 다른 top 카테고리가 없으면 프리뷰 광고를 아예 못 본다 — 의도된 동작(라운드2 검수 #1, 거짓 매칭보다 슬롯 공백이 낫다는 원칙)이지만, 실연동 재고 확보 시 재검토 여지는 있음.
- 로테이션의 "최근 노출 제외" 윈도우(6개)는 카테고리당 템플릿 수(3개)보다 크게 잡아 완전 소진 시 재순환하도록 설계했지만, 같은 카테고리 슬롯이 매우 짧은 간격으로 반복되는 극단적 시나리오에선 그래도 재노출이 발생할 수 있음(하드 캡 아님, best-effort).
- **후킹 카피의 LLM 업그레이드는 미착수**: 지금은 사람이 직접 쓴 24개 큐레이션 문구 + 규칙 기반 폴백(`buildHookCopy`)뿐이다. 실제 상품 설명 전체를 이해해 더 자연스러운 헤드라인을 생성하는 LLM 기반 카피 생성은 API 키·비용이 필요한 후속 업그레이드로 남겨둔다 — 도입 시에도 위 "법적 가드레일"(허위 수치·근거 없는 최상급·가짜 리뷰 금지)과 `hasBannedHookClaim` 검증은 그대로 적용해야 한다.

## 광고 카드 리디자인 — "AD 배지 최소화" (Phase A 확장, 2026-07-26)

### 리서치 근거 (24개 네이티브광고 분석)

David 최종지시의 근거가 된 리서치는 국내외 네이티브 광고(피드형 커머스 카드) 24개 표본을 직접 관찰·분석한 결과다. 공통 패턴:

1. **짧은 라벨이 표준**: 살아남은 네이티브 광고 대부분이 "Sponsored"/"Ad"/"광고" 같은 1~2단어 라벨 하나만 쓴다. "제휴 마케팅 활동의 일환으로 소정의 수수료를 지급받을 수 있습니다" 같은 장문 고지를 카드에 상시 노출하는 사례는 드물다 — 상시 노출된 장문 고지는 오히려 카드를 "명백한 광고판"으로 만들어 콘텐츠와의 동화(assimilation)를 해치고, 정작 유저는 길어서 읽지 않는다(고지 효과 없이 이탈률만 올리는 역효과).
2. **progressive disclosure가 업계 표준**: 상세 고지(누가 스폰서인지, 왜 보이는지, 수수료 구조)는 배지를 탭/클릭/호버해야 나오는 툴팁·모달·랜딩으로 옮겨져 있는 경우가 대부분이다. 미국 FTC의 native-advertising 가이드도 "명확하고 눈에 띄는 1차 고지 + 필요시 접근 가능한 상세"를 허용 구조로 명시한다 — "상시 전문 노출"을 요구하지 않는다.
3. **위장은 예외 없이 규제 대상**: 라벨을 카테고리명·추천 문구로 대체하거나("이런 상품도 있어요" 등 광고성 티가 나지 않는 문구로 치환), 색을 콘텐츠와 완전히 동일하게 해 안 보이게 하는 사례는 (a) 플랫폼 자체 심사에서 거절되거나 (b) 사후 규제 대상이 됐다(국내 표시광고법 "기사형 광고" 규제, 미국 Fashion Nova/Warner Bros FTC 사례 등 — 광고 표시가 "존재"해도 실질적으로 안 보이는 위치·타이밍이면 위법으로 본 판례들이 이 원칙의 근거).
4. **가격/할인율 상시 노출은 업계에서도 갈린다**: 커머스형 배너 광고는 가격을 강조하지만, "콘텐츠에 녹아든" 네이티브 카드(에디토리얼 톤)일수록 가격을 빼고 헤드라인·추천 이유로 승부한다 — 우리 상황(커뮤니티 피드에 자연스럽게 섞이는 것이 핵심 가치)에는 후자가 맞다.

### 법적 안전 원칙 (명문화)

- **배지 상시 노출 필수**: "AD"/"AD · 샘플" 배지는 카드가 렌더되는 순간부터 최초 뷰포트에 항상 보인다 — 접혀 있거나 스크롤/탭해야만 나타나는 위치에 두지 않는다. Warner Bros 등 "명목상 존재하지만 실질적으로 안 보이는 위치의 고지는 위법"이라는 판례 원칙을 그대로 따른다. `test/monetize.test.js`의 "the badge itself ... is unconditionally rendered inside appendAdCard" 테스트가 이 원칙을 코드로 고정한다.
- **위장 절대 금지**: 배지 문구는 카테고리명("기술/IT")·추천 문구("이런 상품도 있어요") 등으로 절대 대체되지 않는다 — 항상 "AD"라는, 광고임이 명확한 단어만 쓴다(기사형광고 규제선). `badgeLabel`은 `makeSlotItem` 한 곳에서만 만들어지고 `"AD"`/`"AD · 샘플"` 두 값 외에는 나올 수 없다.
- **progressive disclosure는 "존재 + 인지 가능 + 접근 가능"이면 적법**: 고지 전문을 상시 렌더하지 않아도, (a) 배지가 광고라는 사실을 항상 알리고(존재+인지가능) (b) 탭하면 고지 전문을 언제든 볼 수 있으면(접근가능) 법적 요건은 충족된다. 이번 변경은 (a)를 배지로, (b)를 팝오버로 분리해 구현했을 뿐, 고지 자체를 없애거나 숨긴 것이 아니다.
- **`sourceLabel`("쿠팡파트너스")는 유지**: 어느 제휴처인지 밝히는 최소 맥락이자 고지의 보강 요소이므로 배지 옆에 계속 노출한다.

- `test/monetize.test.js`에 신규/개정 테스트 다수 추가: 배지 라벨이 정확히 "AD"/"AD · 샘플"인지(카테고리로 위장되지 않는지 포함), 배지가 `<button>`이고 탭 시 `e.stopPropagation()`으로 카드 아웃링크를 트리거하지 않는지, 팝오버가 기본 `hidden`이고 `item.disclosure` 전문을 담고 있는지, 배지 자체는 조건 없이 항상 렌더되는지, `.ad-price`/`adPriceHtml`/`.ad-disclosure-short`/`.ad-sample-note`가 완전히 사라졌는지, WCAG AA 대비(신규 회색 토큰 기준 재검증, 8.15:1)를 그대로 통과하는지. 기존 회귀 테스트(추천이유 칩 분리, 임프레션 dedup, 후킹 카피 우선순위, 정치/성인 배제, 로테이션, 세션 캡 등)는 전부 그대로 유지.
